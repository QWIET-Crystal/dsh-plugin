# 思考通道退化成重复短语 → 空回合且不报错 · 2026-11-06

## 类型

runtime

## 症状

某一轮之后，**每一轮都没有正文、没有工具调用**，界面上看就是"它不肯说话了"。

- 没有报错、没有告警，回合状态是 `completed`；
- 时间线里只剩一条 `reasoning`，长度异常（本例单条 11 万字）；
- 之后每一轮都"正常开头"，几百字之后滑进同一段重复——单轮重复几百到几千次不等；
- 越往后重复量越大，因为这段坏输出已经进了上下文。

一句话：**一轮结束，但既没有正文、也没有工具调用，只有一段超长思考。**

## 判定签名

以下任一即可对号入座（都能从会话日志里复核，不需要猜）：

1. **空回合**：`assistant/message` 的事件里，某轮只有 `reasoning`，**没有配对的 `tool/call`**，也没有 text，`stopReason` 是 `completed`（不是 `error`）。
2. **重复坍缩**：该 `reasoning` 文本里同一短句（本例是 `做。`）连续出现上万次——本例 113,594 字符 / 28,428 次，占该条消息的 99.6%。
3. **残缺的闭合标签**：文本结尾出现 `</arg_value></｜DSML｜tool_calls>` 这类**只有结尾、没有开头**的工具调用标记。
4. **已经在上下文里扎根**：相邻两轮都出现同样的重复段（本例连续 7 轮，重复量 539 / 1555 / 157 / 243 / 1034 / 453 次）。

快速统计（解压会话 JSONL 后跑，Node 22+ 的 `zstdDecompressSync` 能读多帧拼接）：

```sh
node -e "
const fs=require('fs'), z=require('zlib');
const text=z.zstdDecompressSync(fs.readFileSync(process.argv[1])).toString('utf8');
let hit=0, max=0;
for (const line of text.split('\n')) {
  if (!line.includes('assistant')) continue;
  const m=line.match(/做。/g);          // ← 换成你怀疑的那个短语
  if (m) { hit++; max=Math.max(max, m.length); }
}
console.log('含该短语的消息', hit, '单条最多', max);
" <会话文件>.zstd
```

## 根因

三步连锁，缺一不可：

1. **模型在工具参数位退化**。那一步模型本意是发一个工具调用（证据：结尾有工具调用的闭合标记），
   但参数值没有新内容可填，接上了思考里长期存在的口头禅，坍缩成同一短语的无限重复。
2. **开头标记没落进文本**。工具调用的起始标记缺失（模型没写出来，或适配器解析时吃掉了），
   只剩结尾标签——于是整段被当成 **reasoning** 保存，而不是 tool-call。
3. **上下文自强化**。`reasoning` 是隐藏通道：模型看不到自己写了十一万字重复，只知道自己"说了话"；
   下一轮带着这段进 prompt，成了强模式延续。所以每轮开头都正常，几百字后才滑进去。

**它自己走不出来的原因**：空回合 + `completed` 是最难发现的组合（没有错误码），
而且让它"自己检查一下"没用——那句自检同样是带着坏上下文读的。

**时间相邻不等于因果**：事发紧挨着一次写脚本操作，但脚本本身逻辑正常、前后无证据链，不能归因到它。

## 处置与结果

核心原则：**会话日志就是记忆。坏输出一旦落盘就会被当成经历继续长，修复要改记忆，不是改态度。**

实际步骤（全程在线操作，事件数与 seq 保持不变）：

1. 按端口找到监听进程，停掉该实例（不要直接杀所有同名进程）。
2. 备份会话文件与 projcache 到临时目录（必须有回退点）。
3. 解压 `session.*.jsonl.zstd`（多帧拼接，用 `zlib.zstdDecompressSync`）。
4. 定位坏消息：`assistant/message` 里 `reasoning` 含目标短语 ≥ 20 次且**连续成段**的那些（本例 7 条）。
5. 每条**截到第一次出现"单独一行重复短语"之前**，保留前面有信息的分析，末尾加一句标记。
6. 重新压成**单帧** zstd 覆盖原文件（只改文本，事件数/seq 全部不变）。
7. 重启。**直接拉起可执行文件，不要经过 `cmd.exe`**——中文路径在 cmd 命令行里会被 ANSI 代码页弄坏（本例第一次重启就栽在这里）。

## 验证

- 重启后连续 2–3 轮：**有正文、有工具调用**，不再出现空回合；
- 重跑上面的统计：新的会话文件里没有"单条重复成百上千次"的消息；
- 事件数与 seq 与修复前一致（证明只改了文本，没破坏结构）；
- 原备份文件仍在，可随时回滚。

## 早期信号（下次提前收手）

- 一轮结束但既无正文也无工具调用；
- 思考流里同一短语连续出现，尤其是**单独成行**；
- 文本结尾出现残缺的 `</arg_value>` / `</｜DSML｜tool_calls>`；
- 同一模式在相邻两轮都出现 → 已经在上下文扎根，别等它自己停。

## 可迁移的教训

1. **口头禅是概率的锚**：平时是风格，长上下文里就是引力。
2. **空回合 + completed 最危险**：没有错误码，没人会去看。
3. **"不肯好好说"和"被上一段带着说"外面看起来一样，处理方式相反**——先查日志再判断。
4. 一轮里第三次重复同一短句、又没多出任何新事实，就该停手。
