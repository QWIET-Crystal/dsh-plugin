# 大姐按用户要求自我关停（:3080）

- **首次发现**：2026-10-14 22:47:43（`node` PID 49552 绑定 `:3080` 的时刻）
- **持续时长**：一次性动作，非故障
- **现象（用户视角的一句话）**：用户在网页端对大姐说「你自己关一下你自己」。
- **影响范围**：仅大姐 `:3080`。**不是崩溃、不是半死**，是用户显式授权的主动关停。
- **最终归类**：`对策库 #大姐的启动通道`（关停侧对应 `_ops\stop-web.cmd`）

## 证据原文

关停前的落地证据（原样粘贴）：

```
netstat -ano | findstr ":3080"
  TCP    127.0.0.1:3080         0.0.0.0:0              LISTENING       49552
  TCP    127.0.0.1:3080         127.0.0.1:1284         ESTABLISHED     49552
  ...（另有多条 ESTABLISHED 49552 / TIME_WAIT 0）

foreach ($id in 49552,12316) { Get-Process -Id $id }
PID=49552 NAME=node PATH= START=10/14/2026 22:47:43
PID=12316 NAME=msedge PATH= START=10/14/2026 10:32:19
```

判读要点：

- 监听者 **只有一个** PID 49552（`node`），没有第二个可疑进程占用 `:3080`。
- 对端 `12316` 是 `msedge`（用户的浏览器），**不是** DSH 服务；关停只应打服务端 PID。
- **注意一个假阴性坑**：本次 `Get-NetTCPConnection -LocalPort 3080 -State Listen` 返回空（`NO_LISTENER`），
  而 `netstat -ano` 明明显示 `LISTENING 49552`。也就是说**不能用 `Get-NetTCPConnection` 的
  单次结果判定「大姐没在监听」**；`stop-web.cmd` 用 `netstat | findstr LISTENING` 是对的路子。
  （怀疑与 `-State` 参数在本机 PID 归属/权限下的取数路径有关，未深挖；先记为观察项。）
- `Get-CimInstance Win32_Process` 在代理沙箱下报 `拒绝访问`（`exit code: 1`），
  所以**拿不到 `CommandLine` 与 `ExecutablePath`**，PID→进程的取证只能靠 `Get-Process`。
  这与已知的「沙箱下 wmi=denied 降级」同源。

## 判定签名

**这不是故障，是"有意的停止"**。判据（用来避免把用户动作当事故去救）：

1. `:3080` 无监听、宿主 `node` 进程不在；
2. 但日志最后是**明确的关停动作**，没有崩溃栈、没有渲染进程烧核、没有 GPU 崩溃记录；
3. 在此之前有用户的明确指令（"你自己关一下"），且用户没有要求重启 —— 于是守卫应记"用户主动停"，不自动拉起。

## 根因

不是故障。用户主动要求关停大姐（网页端 DSH）。按工作区铁律第 5 条，
「会打断用户正在进行的工作的处置必须先告知用户并得到确认」，故先确认了「关掉不重启」的口径。

## 处置与结果

| 步骤 | 动作 | 结果 |
|---|---|---|
| 1 | 取证：确认 `:3080` 监听者 PID | PID 49552（`node`），唯一监听者 |
| 2 | 向用户确认关停口径 | 用户选「关掉，不重启」 |
| 3 | 落这份存档 | 关停后会话断线，事后无法回填，故前置 |
| 4 | 执行关停：`taskkill /PID 49552 /T /F`（等价 `_ops\stop-web.cmd`） | 见 `_probe` / 下次 `sisters-health` 复查；本会话随之中断，无法在此文件内回写结论 |

**关停后的正确复检方式**（留给下一次会话或二姐/三妹）：
`<workspace>\_ops\sisters-health.cmd` 应显示大姐离线；且**不要**因为「大姐离线」就自动拉起——
按用户意愿，这次是主动关停，属于 guard 的「只报告、不复活」范畴
（`_probe\sisters-hold.cmd list` 可核对是否已在 hold 名单；若未 hold，常驻守护会把「在线→离线」判为边沿并自动拉起，
届时若用户仍希望她保持关闭，应 `_probe\sisters-hold.cmd web on`）。

要再启动：双击 `<workspace>\_ops\start-web.cmd`；登录链接见 `<workspace>\_web-host.log`（**token 每次启动都变**）。
