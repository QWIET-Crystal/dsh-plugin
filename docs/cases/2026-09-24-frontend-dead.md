## 根因

**两个独立问题在同一时间窗叠加：**

1. **`#前端进程死亡`**：服务 `:3080` 的 node 进程 22380 退出，端口无人监听。
2. **`#外壳崩溃`**：Windows 自身在 14:15–14:16 发生连环崩溃（XAML / hermes.dll / twinapi 等系统模块）。**这一条不是 DSH 的问题**，但它是同期所有异常的背景噪声，必须单独隔离出来。

两者是否有因果（外壳崩溃导致 node 退出）**未验证**，不做断言；可确认的只是时间窗高度重合。

## 教训（本次最有价值的一条）

**"HTTP 有应答" 不能用来证明 "服务还在"。** 这三个检查必须各自独立做：

```
1. 进程是否存在        Get-Process node
2. 端口是否有监听      netstat -ano | findstr LISTENING
3. 请求是否真的答      Invoke-WebRequest
```

doctor 因此把「生存层（进程+端口）」和「响应层（HTTP）」拆成**两个独立小节**，且规定：**前一层不健康时不要相信后一层的结论。**
